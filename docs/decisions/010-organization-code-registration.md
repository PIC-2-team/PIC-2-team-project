# ADR-010: 슈퍼 어드민 기관 코드 발급 및 기관 등록 흐름 개선

**상태:** 채택

---

## 배경

기존 시스템에서는 기관 담당자(`INSTITUTION` 역할)가 회원가입 후 대시보드 온보딩에서 기관 이름을 직접 입력하여 기관을 새로 생성하고, 시스템이 8자리 코드를 자동 발급하는 방식이었다.

그러나 현실적인 복지 서비스 운영 관점에서 다음과 같은 문제점이 존재한다:
1. **기관 공신력 및 사칭 위험**: 누구나 임의의 이름으로 기관을 개설할 수 있어 미인가 단체나 비인가자의 기관 개설을 제어할 수 없다.
2. **기관 코드 체계 불일치**: PRD 및 운영 가이드라인에 따른 6자리 고유 기관 코드 체계와 일치하지 않았다.

따라서 플랫폼 운영 주체인 **슈퍼 어드민(`ADMIN`)이 사전 검증된 기관을 등록하고 6자리 기관 코드를 발급**하며, 기관 담당자는 발급받은 코드를 입력해 소속 기관을 등록(Claim)하는 구조로 개편한다.

---

## 결정 사항

### 1. 6자리 기관 코드 체계
- **형식**: 영문 대문자 + 숫자 혼합 6자리 (예: `KNU001`, `SGY101`).
- **중복 방지**: 발급 시 DB 내 중복 여부를 검사하여 유일성을 보장한다.

### 2. 데이터 모델 변경 (`Organization`)
- `ownerId`: 슈퍼 어드민이 기관을 사전 생성할 때 아직 담당자가 지정되지 않은 상태를 지원하기 위해 `nullable = true`로 변경한다.
- `organizationCode`: 6자리 영숫자 문자열로 관리한다.

### 3. 기관 등록 흐름 (Claim & Mapping)
- **슈퍼 어드민**:
  - `POST /api/admin/organizations`: 기관명을 입력받아 6자리 고유 코드를 발급하고 `ownerId = null`인 기관을 생성한다.
  - `GET /api/admin/organizations`: 전체 등록 기관 목록 및 담당자 매핑 여부를 조회한다.
- **기관 담당자**:
  - `POST /api/organizations`: 발급받은 6자리 `organizationCode`를 입력하여 본인의 소속 기관으로 등록한다.
  - 이미 다른 담당자에게 연결된 기관 코드이거나 유효하지 않은 코드일 경우 에러(`CONFLICT`, `NOT_FOUND`)를 반환한다.
  - 등록 성공 시 해당 기관의 `ownerId`를 현재 로그인한 기관 담당자의 ID로 설정한다.

## 검토한 대안과 트레이드오프

| 대안 | 장점 | 단점 | 선택 여부 |
|------|------|------|----------|
| **대안 1. 기관 담당자 생성 후 어드민 사후 승인** | 어드민이 사전에 코드를 발급할 필요 없음 | 비인가 기관 데이터가 DB에 계속 쌓이며, 담당자가 승인 전까지 서비스를 이용하지 못함 | 기각 |
| **대안 2. 어드민이 생성 시 담당자 이메일 지정** | 코드를 전달할 필요 없이 이메일로 자동 매칭 | 담당자가 가입 전이어야 하거나 이메일 오타 발생 시 수정/재발급 번거로움 | 기각 |
| **대안 3. 어드민 6자리 코드 발급 + 담당자 코드 등록(Claim)** | 검증된 기관만 존재하며, 담당자가 코드를 받아 즉시 온보딩 가능하여 현실적이고 유연함 | 오프라인/별도 채널을 통한 코드 전달 필요 (실제 기관 계약 절차와 자연스럽게 부합) | **채택** |
