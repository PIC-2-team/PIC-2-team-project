# ADR-016: 개발 H2 데이터와 읽음 상태 유지

## 상태

승인됨

## 배경

개발 프로필은 H2 인메모리 데이터베이스와 `create-drop`을 사용한다. 백엔드가 재시작되면 데이터와 알림 읽음 상태가 모두 사라지고, 테스트 알림이 다시 시딩될 수 있다.

## 결정

- 개발 프로필의 H2 데이터베이스를 사용자 홈의 파일 기반 데이터베이스로 전환한다.
- Hibernate는 `update` 모드로 기존 데이터를 유지한다.
- 테스트용 미확인 알림은 테스트 보호자 계정을 처음 생성할 때만 시딩한다.

## 고려한 대안

### 인메모리 H2 유지

- 장점: 매 실행마다 깨끗한 개발 데이터로 시작한다.
- 단점: 재시작 후 읽음 상태를 포함한 모든 데이터가 사라지고 시드 알림이 다시 나타난다.
- 제외 이유: 개발 중 읽음 상태와 테스트 데이터를 재시작 뒤에도 유지하려는 요구를 충족하지 못한다.

### 로컬 MySQL 사용

- 장점: 운영과 유사한 데이터베이스를 사용한다.
- 단점: 개발 머신에 별도 MySQL 설치와 실행이 필요하다.
- 제외 이유: 로컬 실행의 추가 설정 부담이 크다.

## 결과와 위험

- 백엔드 재시작 후에도 개발 데이터와 알림 읽음 상태가 유지된다.
- 개발 DB 파일이 사용자 홈에 남으므로, 초기화가 필요할 때는 해당 H2 데이터베이스를 명시적으로 백업한 뒤 처리해야 한다.
